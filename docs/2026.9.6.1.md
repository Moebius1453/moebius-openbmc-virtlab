### D-Bus 是什么

- 实体是一条 Unix socket（/run/dbus/system_bus_socket）+ 管家进程（dbus-daemon）。「挂总线/注册」= 向管家发消息登记信息，没有魔法。
- 五个名词：**bus name**（公司名，全局唯一）、**object path**（房间）、**interface**（职责书）、**property**（数据栏）、**method**（操作栏）。
- 类比：电话总机。服务 = 翻译官（把 /proc、传感器等原始数据翻译成总线上的标准属性）。

---

### 一个「服务」= 三件套

1. **daemon**：C++ 程序（sdbusplus 库）
2. **D-Bus 接口**：YAML 定义 → sdbus++ 生成 C++ 绑定
3. **systemd 单元**：雇佣合同（自动启动、崩溃重启）

### 心脏代码（所有 phosphor 服务 main 的形状）

```cpp
auto bus = sdbusplus::bus::new_default();        // 连系统总线
bus.request_name("xyz.moebius.MemInfo");         // 登记唯一名字
while (true) {
    bus.process_discard();                       // 处理消息
    bus.wait(5000000);                           // 等待（微秒超时）
    memInfo.update();                            // 定时采样推送
}
```

- **process_discard 和 wait 必须成对**。丢了 process_discard = 消息永远躺在队列 → wait 立即返回 → CPU 100% 空转。
- 名字唯一性：两个进程都能启动，名字只有一个主人，另一个排队。

### YAML 接口机制（phosphor 最独特的机制）

- **YAML 是原料，sdbus++ 是加工机器**：`interfaces/yaml/xyz/moebius/MemoryStats.interface.yaml` → 生成 `xyz/moebius/MemoryStats/server.hpp` 等。C++ include 的是成品，不是 YAML。
- **一个接口 = 三个生成物**：
  - `common.hpp`：公共基类（属性钩子的默认实现）
  - `server.hpp`：服务端类（我们继承）
  - `server.cpp`：vtable 注册实现
- 生成代码互相 include，缺一个编译就炸。
- sdbus++ CLI：`sdbus++ -r <yaml根> interface <工序> <接口路径>`，输出走 stdout。
- **接口路径必须点号形式**（`xyz.moebius.MemoryStats`），源码里 `name.replace(".", "/")` 自己定位文件。传斜杠 → 生成的类名/接口名全是 `/`。

### 现代属性模型

- YAML 里一个属性生成三个函数：
  - `memTotal() const`：读缓存 —— **D-Bus 读取走这条路，不经过钩子**
  - `memTotal(v, skipSignal)`：setter —— 存值 + 值变化时自动广播 property_changed
  - `memTotal(v)`：虚拟钩子 —— 默认实现委托 setter
- **钩子在写入/主动上报时被调用，读取不触发**。所以服务必须自己定时采样、主动推送——这正是真实传感器服务的标准形态。
- override 钩子的正确姿势：解析新值后**委托基类**完成入库：

```cpp
uint64_t memTotal(uint64_t value) override
{
    value = readProcMeminfo("MemTotal");
    return MemoryStatsIntf::memTotal(value);   // 限定调用：绕过虚表，直接叫基类版本
}
```

- **返回值 vs 副作用**：return 只是把值交给调用者，调用者不接就蒸发。「存进缓存 + 广播」这类动作住在基类 setter 里，override 把基类函数体整个替换了，必须显式转交。类比：拦下快递员验货，但必须把货转交给原流程入库。

### meson 构建（phosphor 标准）

- `custom_target`：input（原料，变了自动重生成）/ command（加工命令）/ output（成品）/ `capture: true`（把 stdout 收进 output 文件）。
- **output 不能含路径段**——目录层级只能来自 subdir 树：`gen/xyz/moebius/MemoryStats/meson.build` 层层 subdir，输出落构建目录的镜像位置。叶子文件 = 目录树最末端的 meson.build（custom_target 住在这里）。
- subdir 里定义的变量顶层可见；`include_directories('gen')` 自动同时加源码/构建两个目录。

---

### recipe（Yocto 配方）

- 元信息 + **LICENSE 强制项**（md5 用 ${COMMON_LICENSE_DIR} 时抄固定常量）。
- `DEPENDS`：食材（target，进 BMC）vs 厨具（-native，构建机跑）。sdbus++ 工具 = `${PYTHON_PN}-sdbus++-native`。
- `SRC_URI`：原料清单，**所有文件都必须显式登记**（漏了 gen 树报 Nonexistent build file）。
- `S = "${UNPACKDIR}"`：新版 Yocto 禁 S=${WORKDIR}。
- `inherit meson pkgconfig` + `obmc-phosphor-systemd`；`SYSTEMD_SERVICE:${PN}` 声明服务——bbclass 自动装 unit + 开机自启。
- bbappend = 微调上游配方：路径必须镜像上游结构（recipes-phosphor/images/），`IMAGE_INSTALL:append = " meminfo"`。

---

### 变量展开

- `${VAR}` = 解析时文本替换。PN 从配方文件名来。`bitbake -e <recipe> | grep ^VAR=` 查任何变量的最终值（自学标准姿势）。

## 踩坑全记录

| # | 报错/现象 | 原因 | 修复 |
|---|----------|------|------|
| 1 | `S = ${WORKDIR} no longer supported` | 新版 Yocto 弃用 | `S = "${UNPACKDIR}"` |
| 2 | `file could not be found: interfaces` | 配方根目录不在 FILESPATH | interfaces/ 移进 files/ |
| 3 | meson output 不许带路径段 | meson 规则 | 建 gen/ subdir 树 |
| 4 | `Nonexistent build file 'gen/meson.build'` | 新文件没登记 SRC_URI | SRC_URI 加 file://gen |
| 5 | `common.hpp: No such file` | 少生成一个产物 | 加第三个 custom_target（common-header） |
| 6 | 生成的类名全是 `/` | sdbus++ 要点号形式 | `xyz.moebius.MemoryStats` |
| 7 | `'MemoryStats' does not name a type` | 用的旧版命名空间布局 | `sdbusplus::server::xyz::moebius::MemoryStats` |
| 8 | `names the constructor, not the type` | 别名多了尾巴 ::MemoryStats | 去掉尾巴 |
| 9 | 镜像里没有 meminfo | bbappend 放错层级（四层深，模式匹配不上）→ 沉默失败 | 移到 meta-moebius/recipes-phosphor/images/ |
| 10 | SSH `HOST IDENTIFICATION HAS CHANGED` | 新镜像 = 新 host key | `ssh-keygen -R` 删旧记录（重烧镜像的日常） |
| 11 | 属性恒 0 | 现代模型：读取不走钩子，没人更新缓存 | 定时采样 + setter 主动推送 |
| 12 | CPU 100%（1m22s/1m38s） | 丢了 process_discard → 消息不消费 → wait 空转 | 恢复 process_discard（诊断规律：守护进程 CPU~100% = 事件循环写错） |
| 13 | 值还是不落地 | override 只 return 读文件结果，没委托基类入库 | `return MemoryStatsIntf::memTotal(value);` |
